## 1. 三条阻塞，按"卡住了多少东西"排序

### 阻塞 A：**姿势从哪来**没定 → 一次卡住 5 张卡

#### 2026-09-13 补：环境探过了，**这条路现在走不了**（不是选择问题）

试玩反馈"挥刀/一闪好像没绑骨骼、完全没有打击感"之后，我把这条路探到底：

| 探什么 | 结果 |
|---|---|
| `Cascadeur` | ✗ **没装** |
| `Blender` | ✗ **没装**（CREDITS 里早先也记过"本机无 Blender"） |
| `assets/animations/` | 只有 `.gitkeep`——**一个动作素材都没有** |
| 玩家模型 `model_player_congyun_01.glb` | `animations: 0`——**模型里也没有剪辑** |

**结论：代码侧不是瓶颈，素材侧才是。** 现在能动的只有两件事：

1. **装一个能出动作的工具**（Blender 免费、~300MB；Cascadeur 免费 indie），
2. 或者**取一套 CC0 动作包**（但 07 §1 已判"剑术库不匹配"——通用动作多、剑戟动作少）。

#### 打样三步（**先做 3 个动作验证管线，再谈铺量**）

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 | 出 3 个动作：`attack_light_01` / `guard_raise` / `hit_light`（**60fps**） | 三个 FBX/GLB 落在 `assets/animations/` |
| 2 | 导入 Godot：挂 `AnimationPlayer`、**帧率设 60**、挂在主角的 `VisualModel` 下 | 编辑器里能预览到动作 |
| 3 | **按逻辑帧驱动**（04 §12）：状态机给帧号，动画只做 `Seek(logicFrame/60)` | 调试面板的 anim/logic 偏差 ≤2 帧 |

> ⚠️ 第 3 步的"接口"我还没做：现在 `HumanoidAnimator` 是**纯程序化**的，
> 它不会去消费真动作剪辑。所以真动作一到位，还需要一小段"剪辑通道"
> （找 `AnimationPlayer` → 有对应剪辑就用它、按帧 `Seek`；没有就退回程序化）。
> 这一段是纯代码、我可以先做——**但**没有素材就没法验证它对不对，
> 所以建议**等第 1 步有素材了一起做**，免得做出一个没验过的通道。

> 教训记一笔：`AttackData.AnimName` 这个字段**一直存在、一直没人读**（死配置清单里的一条）。
> 也就是说"动画名字"这个接口**早就预留好了**，缺的从来不是接口，是**素材与消费方**。

T38（动画覆盖）、T25（主角骨架）、T26（笼手）、T27（敌人）、T29（女主）
**全都在等同一样东西：动作从哪来。**

现状 `HumanoidAnimator` 只有 5 类姿势，而且是**直接手写骨骼旋转**。
要补到 07 §1.1 的 ~28 个，手写不可行。

三条候选：**程序化扩**（可控、零依赖、工时不可行）／**Cascadeur**（免费 indie，能出真动作，
但要建导入与帧对齐管线）／**CC0 动捕库**（最快，但 07 §1 已经判定剑术动作库不匹配）。

→ **建议：先打样 3 个动作验证管线，再决定要不要铺量。** 这正是 T24 的真正内容。

### 阻塞 B：**没有遭遇战编排** → "它还不是一个关卡"

现在能玩的本质是一个**道场沙盒**：`LevelBlockout` 按圆环刷 3 个敌人，
`Dojo` 里手摆了几个假人 + 一尊魔骸。**没有"遭遇区 → 触发 → 清场 → 推进"这条链**，
也没有存档点（03 §7 的鬼火）。

好消息：**T32 已经把地基铺好了**——L01 白盒里已经有 `combat_area` 组标记和 `Path` 路径点，
遭遇战可以直接挂在这些标记上。而且这条**不需要美术、不需要动画**，可以立刻开工。

### 阻塞 C：**M1 的验收从没做过** → 后面的投入都是赌注

M1 的唯一标准是 **"弹开成功时会想再试一次"**，只能由真人试出来。

现在条件其实**已经齐了**：架势槽能读（弹开 +18 vs 普攻 8）、弹开音高递增有了、
重开 ≤3 秒有了。该做一次**正式验收**，而不是零散试玩。
如果这条不成立，M5 的关卡铺量全是白做。
