# 06 · 开发路线图

> 核心策略：**先做垂直切片（Vertical Slice），再做内容铺量。**
> M5 结束时必须有一个"能端出来给人玩 10 分钟"的东西。
> 在此之前不写任何第二关的内容。

## 0. 口径修订（2026-09-12 · 制作人）

> **本节优先于本文档其余所有内容。** 下面的 M0~M8 表格是原始规划，保留作为参考，
> 但**里程碑编号、内容与排期以本节为准**。
>
> 依据：[08-顶层设计评审](08-顶层设计评审.md) §3 P0-1 / P0-2、§4 红线 1-2。

### 改了三件事

**1. 插入 M0.5「可玩闭环」，作为当前唯一目标。**

原计划前 5 周（M0~M2）没有任何"能被人玩"的东西，而本项目的成败标准
是"玩家第一次弹开后会不会自发再试一次"——这是个**只能被打出来、不能被推理出来**的问题。
所以先插一个最小可玩闭环：`CombatActor` + 判定框 + 木桩 + 三连击 + 顿帧 + 占位音效。
**在"能砍木桩并感觉到反馈"之前，不写任何新系统、不做任何新内容。**

**2. 把 M5 垂直切片当作 1.0 的发布目标。**

原来的 M5 验收标准（"新人 5 分钟学会格挡 / 熟练玩家 90 秒打死第一个 BOSS /
不弹开也能通关 / 死亡重开 ≤3 秒"）已经是一条**完整、可发布**的产品线。
把它做完并发出去收反馈，比闷头做 40 周更有价值。

| | 旧口径 | **新口径** |
|---|---|---|
| 1.0 发布内容 | 序章 + 第一~三章 + 终章，3.5~4 小时 | **序章 + 第一章，一个 BOSS，15~20 分钟**（= 原 M5） |
| 1.0 何时能发 | 第 20.5 周（原 M7） | **第 12.5~15.5 周**（原 M5 + 难度/可及性） |
| 3.5~4 小时流程 | 1.0 的目标 | **1.0 之后**的内容扩充（原 M7），视反馈决定做不做 |

> 理由：5 周做出"3 章 + 3 个 BOSS + 鬼力三元素 + 升级三线 + 道具 + 收集 + 挑战模式"
> 不是"排期紧"，是排期不存在。按 07 文档的资产量算，那部分约需 220 个动作，
> 现实工期是 12~16 周。**承诺一个做不出来的时长，比承诺一个短但做得出来的时长危险得多。**

**3. 原 M6（难度系统 + 可及性 + 道场 + 教学）并入发布门槛。**

因为它承载的正是"手残玩家能不能通关"——这是 01 文档的三大体验指标之一，
**不能算作锦上添花，必须算进 1.0**。

## M0 · 骨架与裁决器（1 周）

**目标**：一个能跑的空项目 + 一个已经被测试验证过的战斗裁决内核。

### 任务
1. Godot 新建项目（勾选 .NET），`Forward+`，主场景 `scenes/boot/Boot.tscn`
2. 写 `Oniblade.csproj` / `.gitignore` / `.editorconfig`（见 04 文档 §2）
3. `git init` + 首次提交
4. 建目录骨架（`scenes/` `data/` `src/` `tests/`）
5. 写 `Frames.cs`（`PerSecond = 60`）
6. 写 `Verdict.cs` / `Snapshots.cs` / **`CombatResolver.cs`**
7. 建 xUnit 测试工程，写 **10 个测试**（6 条规则 + 4 个优先级冲突）并跑绿
8. 写 `AttackData.cs` / `DifficultyProfile.cs`，在编辑器创建 2 个 `.tres` 验证 Inspector
9. 写 `DebugOverlay.cs`（F1 面板骨架，能显示文字即可）
10. 灰盒场景：`GridMap` 或几个 `CSGBox3D` 当地板

### 验收标准
- [ ] `dotnet test` 全绿，10 个测试通过
- [ ] 游戏能启动，按 F1 弹出一个空的调试面板
- [ ] 编辑器里能创建 `AttackData` 资源并看到分组好的属性栏
- [ ] 项目能在 CLI 下 `dotnet build` 成功（验证 CI 可行性）

### 为什么先做裁决器
裁决器是全项目最不能出错的地方。它没有依赖、可以单测。
先把它做对、测透，后面所有战斗代码都是在调用它，而不是在重复实现判定。
**如果先做角色，一定会写出散落各处的 `if (isParrying && ...)`，后期重构代价极高。**

## M1 · 三连击 + 输入缓冲（2 周）

**目标**：玩家能打出有手感的三连击，且"按了就有反应"。

### 任务
1. `CombatActor.cs` 骨架（`ActorId` / 血 / 体干 / 顿帧 / 持有状态机）
2. `StateMachine.cs` + `ActorState.cs`（POCO，延迟切换）
3. `IdleState` / `MoveState` / `SprintState`
4. `AttackState`（内部 `ComboIndex` 支持三连）
5. `PlayerInputBuffer.cs`（8 帧缓冲，`Consume` 语义）+ 单测
6. `PlayerActor.cs` + `PlayerCameraRig.cs`（越肩视角 + 鼠标视角）
7. `LockOnSystem.cs`（锁定/切换目标）
8. 接入 Mixamo 动画（3 个攻击动作 + 待机 + 移动）
9. `AttackData` 实例化 3 个（轻斩壹贰叁）+ 导入 FPS 对齐 60

### 验收标准
- [ ] 三连击能顺畅打出，且在后摇中段按攻击能接上下一段
- [ ] 后摇中按闪避能取消（第 6 帧起）
- [ ] 狂按攻击键**不会**出现"卡在第 1 段出不来"或"跳过第 2 段"
- [ ] 调试面板显示 `anim frame` 与 `logic frame` 偏差 ≤ 2
- [ ] 输入缓冲单测全绿

### 风险
- Mixamo 动画是 30fps，需要重采样到 60fps。**在 M1 就解决，别拖**
- 动画与帧数据对齐问题会在 M1 首次暴露，一定要把面板的同步检查做出来

## M2 · 格挡 + 弹开 + 顿帧（2 周）

**目标**：弹开有"上头"的反馈。这是整个项目最关键的 2 周。

### 任务
1. `GuardState`（记录进入帧，判定弹开窗）
2. `DeflectState`（12 帧特殊状态）
3. `Hitbox.cs`（形状查询）+ `Hurtbox.cs`（Area3D）
4. `CombatArbiter.cs`（收集 → 排序 → 结算）
5. 顿帧（逐 actor `_hitStopFrames`）
6. **音效占位**：弹开的金属"叮"、格挡的钝响、命中的切割声
7. 火花粒子 + 镜头抖动
8. **弹开音高递增**（连弹音高 +2 半音/次）
9. 弹开窗参数接到 `DifficultyProfile`

### 验收标准
- [ ] 假人横斩能被弹开，有顿帧 + 火花 + 音效
- [ ] 连续弹开 5 次，音高明显递增（自己听着"爽"）
- [ ] 从攻击后摇取消进防御的前 4 帧**弹不开**（防连打生效）
- [ ] 但同情况下**仍然格挡成功、不掉血**（惩罚只惩罚效率）
- [ ] 背后被攻击时格挡无效（角度判定生效）
- [ ] 找个人试玩，问他"弹开爽吗" → 答案是"爽"

### 注意
如果 M2 结束弹开手感不好，**不要往下走**。
花时间调参数（前摇、顿帧长度、音效、粒子），这是项目成败的地基。
调参靠 `data/attack/*.tres`，零编译。

## M3 · 体干 + 忍杀 + 第一个敌人 AI（2 周）

**目标**：一个"像样的敌人"，能打一场完整的遭遇战。

### 任务
1. `PostureMeter.cs`（纯逻辑，含"血量越低恢复越慢"规则）+ 单测
2. `GuardBreakState`（双方）
3. `DeathblowExecuteState`（忍杀演出 + 慢镜）
4. `EnemyActor.cs` + `EnemyBrain.cs`（分层状态机，10Hz 决策）
5. 第一个敌人：**魔骸足轻（刀）** —— 只会横斩 + 二连斩
6. `EnemyProfile` 资源（Aggression / ReactionDelay / ComboChance / AttackInterval）
7. 魂掉落 + 吸收（基础版）
8. 敌人受击/死亡动画（Mixamo）

### 验收标准
- [ ] 能靠弹开磨满敌人体干 → 出现忍杀标记 → 按处决键发动忍杀
- [ ] 敌人攻击前摇 ≥ 24 帧，肉眼能看清（找人验证）
- [ ] 敌人不会零帧转身，不会 8 帧内连出两招
- [ ] 敌人连段后有 ≥ 20 帧空隙，玩家能反打
- [ ] **AI 不读输入**：玩家按攻击不会导致敌人取消前摇
- [ ] 完全不弹开，只用闪避+普攻也能打死它（验证路径 B 可行）

## M4 · 拼刀 + 一闪家族（2.5 周）

**目标**：5 种交战结果（命中/格挡/弹开/拼刀/一闪）全部可复现。

### 任务
1. `ClashState`（10 帧顿帧 + 8 帧输入窗 + 连败保险）
2. 一闪 buff 统一机制（`IssenKind` + 授予/过期）
3. `IssenState`（22 帧后摇，不可取消）
4. **真一闪的输入时扫描**（预测敌人"距命中还有几帧"）
5. **一闪安全窗**（按早了转格挡，不挨打）← 手残友好核心
6. 一击必杀结算（杂兵即死 / 精英削体干 / BOSS 削减 + 硬直）
7. 连锁一闪（瞬移 + 时停 + 上限 3 连）
8. 一闪的慢镜 + 黑白闪 + 血雾 + 镜头推近
9. 危攻击预警（红「危」+ 三类音高 + 图形符号）

### 验收标准
- [ ] 5 种交战结果都能稳定复现
- [ ] 真一闪在敌人命中前 6 帧内按攻击 → 成功；按早了 → 转格挡且不掉血
- [ ] 连锁一闪能连 3 个敌人，演出流畅
- [ ] 一闪落空有 30 帧无防御硬直（有代价，但不是即死）
- [ ] 拼刀连输 2 次后第 3 次自动赢（保险生效）
- [ ] 危·突刺/横扫/抓取三种音高可分辨（闭眼听能区分）

## M5 · 垂直切片 ★（3 周）

**这是真正的里程碑。到这里项目就已经"成立"了。**

### 任务
1. **第一个 BOSS「鬼哭」**（双刀魔骸武士，2 阶段）
   - P1：横斩 + 二连斩 + 危·突刺（横斩/二连斩教**弹开**，危·突刺教**看破**——弹开对危无效）
   - P2：加入拼刀往返演出 + 危·横扫
2. 第一个完整关卡：**岐阜城下**（约 10 分钟流程）
   - 3 段遭遇战 + 1 段探索 + 1 个精英 + BOSS
3. 存档点（鬼火）+ 存档/读档 + 死亡重开流程
4. HUD（血条 / 体干条 / 魂数 / 鬼力槽 / 忍杀提示）
5. 主菜单 + 暂停菜单
6. 死亡/复活流程（1 次复活机会）
7. 基础音效与 BGM（可用免费素材）
8. 环境美术占位（免费资产，不追求好看）

### 验收标准（垂直切片验收，全部必须满足）
- [ ] 新玩家不看说明，5 分钟内学会格挡，10 分钟内偶然成功弹开
- [ ] 熟练玩家能在 90 秒内用弹开+一闪打死鬼哭
- [ ] 同一个人玩两次，第二次明显更轻松（熟练度在起作用）
- [ ] 完全不弹开、不用一闪，靠闪避+普攻能打死鬼哭（路径 B 验证）
- [ ] 连续玩 15 分钟不腻
- [ ] 能完整走一遍：主菜单 → 关卡 → BOSS → 胜利 → 回到主菜单
- [ ] 死亡 → 重开 ≤ 3 秒

### 决策点
M5 结束后做一次判断：
- **如果核心循环好玩** → 继续 M6/M7 铺内容
- **如果不好玩** → 停下来调整核心机制，**绝不要靠加内容来掩盖手感问题**

到这一步，其实已经可以作为一个"小游戏"发布了。

## M6 · 难度系统 + 可及性 + 道场（3 周）

**目标**：手残玩家能打完第一章。

### 任务
1. `DifficultyManager`（Autoload）+ 4 个 `.tres` 难度档
2. 设置菜单（难度 / 辅助选项 / 键位重映射 / 画面 / 音量）
3. `AdaptiveDifficulty.cs`（DDA，含触发/上限/重置）
4. **道场（练习房）**：木桩 / 弹开假人 / 看破假人 / 拼刀假人 / BOSS 幻影
5. 教学关（序章 + 第一章的渐进教学）
6. 半自动防御、节拍提示、危攻击分型音效、预警圈
7. 色盲友好：体干条形状区分 + 危攻击图形符号
8. 晕动症选项：镜头抖动滑条、慢镜时长、闪烁减弱

### 验收标准
- [ ] 找一位**不玩动作游戏**的人，只教格挡+闪避+普攻 → 能打过鬼哭（允许死 10 次以上）
- [ ] 四档难度切换后，弹开窗/敌人节奏有明显可感差异
- [ ] 连续死 3 次同一 BOSS，第 4 次明显更容易（DDA 生效，且玩家说不清为什么）
- [ ] 道场里能立刻重开 BOSS（死后 ≤ 1 秒）
- [ ] 关掉所有辅助选项后，游戏体验与默认无差异（辅助不污染默认体验）
- [ ] 全部按键可重映射

## M7 · 内容铺量（5 周）

**目标**：3.5~4 小时可通关的完整流程（序章 + 第一~三章 + 终章）。

### 任务
1. 第二章 · 安土城（教一闪 + 拼刀）+ BOSS「焰」
2. 第三章 · 比叡山（教鬼力/蓄力）+ BOSS「咒」
3. 终章 · 第六天魔王（简化版，2 阶段）+ 2 个结局分支
4. 噬魂笼手/鬼力系统（三元素）+ 魂升级（体/技/魂三条线）
5. 消耗道具（药、符、炸弹）+ 快捷栏
6. 收集要素（魂之碑）+ 支线（魔骸讨伐）
7. 挑战模式（BOSS 连战 / 限时 / 无伤评价）—— 复用已有 BOSS，性价比极高

### 验收标准
- [ ] 完整流程可通关，有结局演出
- [ ] 三条路径在每一关都可行（对照 05 文档检查清单）
- [ ] 每个新机制都有专属无惩罚练习场景
- [ ] 每个 BOSS 只考 1~2 个机制
- [ ] 通关时长 200~260 分钟
- [ ] 每个 BOSS 阶段过渡不断崖（P2 开场是玩家已会的机制）

## M8 · 平衡与发布（3 周）

### 任务
1. **平衡**：按 F8 战斗统计数据调整，不凭感觉
2. **性能**：目标 1080p / 60fps，同屏 8 敌人不掉帧
3. **美术替换**：把占位资产换成最终资产（如果做）
4. **音频**：最终音效与 BGM
5. 存档格式稳定化 + 版本迁移
6. 导出预设（Windows / Steam Deck）
7. 崩溃处理、日志、设置持久化

## 每周节奏建议

| 日 | 做什么 |
|---|---|
| 周一~周三 | 写新功能 |
| 周四 | 调参 + 手感打磨（只看调试面板和 F8 统计） |
| 周五 | 找人试玩（哪怕只有一个人） |
| 周末 | 按试玩反馈改，或补内容 |

**「每周至少让一个人玩到」**是这个项目最重要的纪律。
手感是主观的，只有真人的反应能告诉你真相。别自己闷头做三个月。

## 什么时候算"可以发布"

- M5 完成 → 可以发布一个"战斗 DEMO"（免费，用来收反馈）
- M7 完成 → 可以发布 1.0（3.5~4 小时流程 + 挑战模式）
- M8 完成 → 打磨版

**不要等"全部做完"才给人玩。** M5 就应该有一个公开可玩的版本。
