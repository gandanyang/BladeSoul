## 二、冻结的接口

### 2.1 目录三层铁律

```
scenes/   只放结构（节点树、实例）
data/     只放数值（.tres，改这里不用编译）
src/      只放逻辑（C#）
tests/    纯逻辑单元测试（xUnit，脱离引擎跑）
tools/    开发脚本
assets/   原始素材（模型/贴图/音频/动画）
```

`scripts/` 与 `resources/` 是历史遗留，**已废弃**（迁移见 `src/`、`data/`）。

### 2.2 命名空间

`Oniblade.Utils` / `Oniblade.Combat` / `Oniblade.Combat.Data` / `Oniblade.Player`
/ `Oniblade.Enemies` / `Oniblade.Core` / `Oniblade.UI` / `Oniblade.Levels` / `Oniblade.Dev`

约定沿用 04 文档 §17：file-scoped namespace，私有字段 `_camelCase`，
帧相关的数字**必须带 `Frames` 后缀**。

### 2.3 输入动作（唯一合法的 action 名）

| 动作名 | 绑定 | 说明 |
|---|---|---|
| `attack` | 鼠标左键 / J | 攻击，同时是一闪的发动键 |
| `guard` | 鼠标右键 / K | 按住格挡；进入后的窗口内被命中即弹开 |
| `dodge` | 空格 | 垫步闪避 |
| `lock_on` | 鼠标中键 / Q | 锁定 |
| `interact` | F / E | 交互、拾取、处决提示 |
| `oni_magic` | U | 鬼力（鬼之笼手） |
| `item_use` | R | 使用道具 |
| `sprint` | 左 Shift | 冲刺 |
| `move_forward/back/left/right` | WASD | 移动 |
| `pause` | Esc | 暂停 / 释放鼠标 |

**没有 `jump`。** 本作不设跳跃（鬼武者式地面剑戟），
02 文档里「危·横扫」的"跳跃/闪避"按**闪避**实现。
`block` / `prosthetic` / `deathblow` / `crouch` 这些旧名一律不要再用：
格挡是 `guard`，忍杀触发时复用 `attack`。

### 2.4 帧基

**60fps 整数帧是唯一的时间单位。** `src/Utils/Frames.cs` 是唯一换算入口。
秒只允许出现在 UI、音频、Tween 三处。

### 2.5 裁决器签名（全项目最核心的契约）

```csharp
// src/Combat/CombatResolver.cs —— 纯函数，零 Godot 依赖
public static ResolveResult Resolve(in AttackerSnapshot atk, in DefenderSnapshot def);
```

优先级顺序（命中即返回，改顺序等于改游戏）：

```
1. 无敌帧            → Miss
2. 一闪 buff + 可闪   → Issen
3. 双方都在判定帧      → Clash
4. 弹开窗            → Deflect
5. 格挡且夹角 ≤ 70°   → Block（体干满则 GuardBreak）
6. 其余              → Hit
```

### 2.8 并行开发用的接口（2026-09-12 冻结）

为了让多个执行 agent 能真正并行而不互相踩，以下接口由制作人统一冻结，
**实现者在各自的类里实现/调用，但不得改签名**：

| 文件 | 内容 | 谁用 |
|---|---|---|
| `src/Core/EventBus.cs` | Autoload 单例。事件：`HealthChanged` `PostureChanged` `PostureBroken` `HitResolved` `ActorDied` `DeflectChainChanged` `SoulGained` `DifficultyChanged` | 全员 |
| `src/Core/GameEvents.cs` | `HitEvent` / `DeflectChainEvent` / `SoulGainedEvent` 载荷 | 全员 |
| `src/Combat/ICombatActorDebug.cs` | 战斗单位对外暴露的**只读**状态，**只给调试面板与统计用** | 战斗单位实现，UI 消费 |
| `src/Combat/IDebugCheatable.cs` | 调试**写入侧**（F4 无敌）。**只许调试面板用，正式战斗逻辑永远不许读它** | 战斗单位实现，UI 消费 |
| `src/Combat/CombatTuning.cs` | 弹开窗的**唯一计算入口**（难度档 + 升级 + DDA → clamp），见 08 §3 P1-3 红线 | 所有人 |
| `src/Combat/Hitbox.cs` / `Hurtbox.cs` | 判定框（同步形状查询）/ 受击框（`Monitoring=false, Monitorable=true`）。各自加入 Godot 组 `hitbox` / `hurtbox` | 战斗代码、调试面板画线框 |
| `src/Core/CombatArbiter.cs` | 每帧：收集重叠 → 按 `ActorId` 排序 → 裁决 → 落地。`ProcessPhysicsPriority = 100`（晚于所有战斗单位） | 场景里放一个 |
| `src/Audio/CombatSfx.cs` + `src/Audio/AudioDirector.cs` | `PlayCombat(sfx, pitchScale, volumeDb)` / `ResetDeflectChain()` / `DeflectPitchScale` | 战斗代码调用 |
| `src/Combat/CombatResolver.cs` | `Resolve(in AttackerSnapshot, in DefenderSnapshot)` | 仲裁器调用 |
| `src/Progression/SoulType.cs` | 赤魄 / 黄魄 / 青魄 / 白魄 | 魂系统 |

| `src/Combat/IAttackEvasionListener.cs`（T13） | **`Verdict.Miss` 的唯一可观测出口**。原先 `ReceiveVerdict` 对 Miss 直接 return（不发事件、不 `MarkHit`），闪避的奖励闭环是断的 | 闪避状态实现它；`CombatArbiter` 只加 2 行广播 |
| `IHealHost`（定义在 `States/HealState.cs` 内，T18） | 喝血次数只属于玩家，不该进 `CombatActor`。同 `IGuardInput` 的先例 | `PlayerActor` 实现 |
| `CombatActor.SpawnTransform` + `virtual ResetForBattle()`（T14） | 已存在的基类**只加不改**：`_Ready` 末尾捕获出生变换；原地重开协议靠它复位 | `BattleReset` 调用 |
| `src/Core/BattleReset.cs`（T14） | 原地重开协议：复位所有战斗单位，**不重载场景**。调试面板 F7 已改为调用它（找不到才退回重载场景） | 场景里放一个实例 |
| `ActorStats` 新增字段（T18/T14） | `HealCharges` / `HealStartupFrames` / `HealDrinkFrames` / `HealRecoveryFrames` / `HealPercent` / `DeathRestartDelayFrames` | 全部经 `.tres` 配置 |

**规矩**：任何战斗逻辑都不许走 `ICombatActorDebug`（它是只读视图，不是 API）；
任何 UI 都不许引用 `CombatActor` 具体类型。这条界线的存在，就是"调试面板能和战斗管线并行开发"的全部原因。

**订阅者纪律**：`EventBus` 是 static 单例上的 C# event，会强引用订阅者。
每个订阅者必须在 `_ExitTree()` 里退订，否则节点释放后仍被持有。

## 三、对 04 文档的修正（已落到代码，04 已同步）

1. **拼刀要求双方都在判定帧。**
   `DefenderSnapshot.IsActive`，不是"在出招（IsAttackAction）"。
   否则砍一个正在挥空后摇的敌人也会判成拼刀，玩家会觉得莫名其妙。
2. **`CancelFromRecoveryFrame` 量的是后摇内的偏移，不是绝对帧号。**
   轻斩壹：后摇 14 帧、偏移 6 → 第 18 帧起可取消。用 `-1` 表示不可取消。
   原来的 `CancelFromFrame` 会被读成绝对帧号，无头自检当场抓到了这个歧义。
3. **裁决器不吃 `AttackData`。** 它是 Godot `Resource`，塞进"纯函数"会让
   xUnit 测试抛未初始化异常。改为不含 Godot 类型的 `AttackTraits`，
   由 `AttackData.ToTraits()` 转换。
4. **输入缓冲用 `enum PlayerAction`，不用 `StringName`。** 同理：
   `StringName` 会触碰引擎互操作，用了就再也测不了输入缓冲。
5. **补齐 `AttackData.AdvanceDistance`。** 02 文档 §2.1 有"位移"列，04 的字段表漏了。

## 四、优先级（按"能不能让游戏早一天成立"排序）

| 优先级 | 任务 | 为什么是这个顺序 |
|---|---|---|
| **P0** | 调试面板 F1（04 §13） | 没有它，后面每一行调参都是盲人摸象 |
| **P0** | `CombatActor` + `Hitbox`/`Hurtbox` + 木桩 | 让"砍中"这件事第一次发生 |
| **P0** | 玩家三连击 + 输入缓冲 + 帧精确 seek | 手感的第一个可感知版本（M1） |
| **P1** | 格挡 + 弹开 + 顿帧 | **本项目的立命之本**，唯一必须"上头"的机制 |
| **P1** | 体干 + 忍杀 + 第一个敌人 AI | 第一条完整战斗闭环（M3） |
| **P2** | 拼刀 + 一闪家族 + 慢镜 | M4，爽点扩面 |
| **P2** | 音频占位（弹开音高递增） | 02 文档：手感的 50% 在音频 |
| **P3** | 垂直切片（BOSS + 关卡 + 存档） | M5，项目"成立"线 |

**不建议现在做的事**：美术替换、剧情文本铺量、多武器、挑战模式。
它们都不解决"好不好玩"这个当前唯一的未知数。
