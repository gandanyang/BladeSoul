## 二、冻结的接口

### 2.1 目录三层铁律

```
scenes/   只放结构（节点树、实例）
data/     只放数值（.tres，改这里不用编译）
src/      只放逻辑（C#）
tests/    纯逻辑单元测试（xUnit，脱离引擎跑）
tools/    开发脚本
assets/   原始素材（模型/贴图/音频/动画）
```

`scripts/` 与 `resources/` 是历史遗留，**已废弃**（迁移见 `src/`、`data/`）。

### 2.2 命名空间

`Oniblade.Utils` / `Oniblade.Combat` / `Oniblade.Combat.Data` / `Oniblade.Player`
/ `Oniblade.Enemies` / `Oniblade.Core` / `Oniblade.UI` / `Oniblade.Levels` / `Oniblade.Dev`

约定沿用 04 文档 §17：file-scoped namespace，私有字段 `_camelCase`，
帧相关的数字**必须带 `Frames` 后缀**。

### 2.3 输入动作（唯一合法的 action 名）

| 动作名 | 绑定 | 说明 |
|---|---|---|
| `attack` | 鼠标左键 / J | 攻击，同时是一闪的发动键 |
| `guard` | 鼠标右键 / K | 按住格挡；进入后的窗口内被命中即弹开 |
| `dodge` | **左 Shift**（方向 + Shift） | 垫步闪避。**2026-09-13 从空格改到 Shift**，把空格让给跳跃 |
| `jump` | **空格** | **跳跃**（2026-09-13 解冻，见 §七） |
| `lock_on` | 鼠标中键 / Q | 锁定 |
| `interact` | F / E | 交互、拾取、处决提示 |
| `oni_magic` | U | 鬼力（鬼之笼手） |
| `item_use` | R | 使用道具 |
| `sprint` | 左 Shift（长按） | 冲刺。**与 `dodge` 共键**：方向 + Shift = 垫步，长按 = 冲刺 |
| `move_forward/back/left/right` | WASD | 移动 |
| `pause` | Esc | 暂停 / 释放鼠标 |

**★ 2026-09-13：本作有跳跃（原"不设跳跃"的冻结已被推翻）。**

原文是"**没有 `jump`**。本作不设跳跃（鬼武者式地面剑戟）"。
**项目主人裁定推翻**，理由是参考前提本身：**《只狼》与《鬼武者 剑之道》都有跳跃**——
而这两部正是本作的参照系，本作不做跳跃没有道理。

推翻后的四处连带改动：

1. `jump` 成为合法动作，绑**空格**（新）
2. `dodge` 从空格改到**左 Shift**，与 `sprint` 共键（方向 + Shift = 垫步，长按 = 冲刺）
3. 02 §3「危·横扫」那行的"可看破（**跳跃/闪避**）"**重新按字面生效**——两条解法都成立
4. **跳跃不是无敌帧**：它是"**离开地面判定**"，与闪避的**无敌帧**是两套机制，
   必须分开实现，否则会互相取消（T41 的硬约束）

> ⚠️ 这条推翻改的是**设计前提**，不只是加一个键位。凡是引用过
> "地面剑戟 / 不设跳跃"的地方（含关卡净空约束的推理）都要按新前提复核一遍。

`block` / `prosthetic` / `deathblow` / `crouch` 这些旧名一律不要再用：
格挡是 `guard`，忍杀触发时复用 `attack`。

### 2.4 帧基

**60fps 整数帧是唯一的时间单位。** `src/Utils/Frames.cs` 是唯一换算入口。
秒只允许出现在 UI、音频、Tween 三处。

### 2.5 裁决器签名（全项目最核心的契约）

```csharp
// src/Combat/CombatResolver.cs —— 纯函数，零 Godot 依赖
public static ResolveResult Resolve(in AttackerSnapshot atk, in DefenderSnapshot def);
```

优先级顺序（命中即返回，改顺序等于改游戏）：

```
1. 无敌帧            → Miss
2. 一闪 buff + 可闪   → Issen
3. 双方都在判定帧      → Clash
4. 弹开窗            → Deflect
5. 格挡且夹角 ≤ 70°   → Block（体干满则 GuardBreak）
6. 其余              → Hit
```

**T52 确立的两条机制口径**（项目主人口述裁定，不许再含糊）：

1. **处决键 = 交互键 F/E，普攻键绝不许处决**。同键会让"砍几刀再处决"退化成
   "一想补刀就进处决"，玩家再也感受不到"我先打崩它、再从容补刀"的节奏。
2. **处决期间玩家全程无敌**，且**不新增裁决分支** —— 只让
   `PlayerActor.IsInvulnerableNow` 在演出期间为真。`CombatResolver` 规则 1 早就在读它
   （判 `Miss`，连一闪都打不中），所以这条对**所有**敌人同时生效。
   另造一条分支会把已有单测覆盖的规则撕成两半。

**规矩**：任何战斗逻辑都不许走 `ICombatActorDebug`（它是只读视图，不是 API）；
任何 UI 都不许引用 `CombatActor` 具体类型。这条界线的存在，就是"调试面板能和战斗管线并行开发"的全部原因。

**订阅者纪律**：`EventBus` 是 static 单例上的 C# event，会强引用订阅者。
每个订阅者必须在 `_ExitTree()` 里退订，否则节点释放后仍被持有。

## 三、对 04 文档的修正（已落到代码，04 已同步）

1. **拼刀要求双方都在判定帧。**
   `DefenderSnapshot.IsActive`，不是"在出招（IsAttackAction）"。
   否则砍一个正在挥空后摇的敌人也会判成拼刀，玩家会觉得莫名其妙。
2. **`CancelFromRecoveryFrame` 量的是后摇内的偏移，不是绝对帧号。**
   轻斩壹：后摇 14 帧、偏移 6 → 第 18 帧起可取消。用 `-1` 表示不可取消。
   原来的 `CancelFromFrame` 会被读成绝对帧号，无头自检当场抓到了这个歧义。
3. **裁决器不吃 `AttackData`。** 它是 Godot `Resource`，塞进"纯函数"会让
   xUnit 测试抛未初始化异常。改为不含 Godot 类型的 `AttackTraits`，
   由 `AttackData.ToTraits()` 转换。
4. **输入缓冲用 `enum PlayerAction`，不用 `StringName`。** 同理：
   `StringName` 会触碰引擎互操作，用了就再也测不了输入缓冲。
5. **补齐 `AttackData.AdvanceDistance`。** 02 文档 §2.1 有"位移"列，04 的字段表漏了。

## 四、优先级（按"能不能让游戏早一天成立"排序）

| 优先级 | 任务 | 为什么是这个顺序 |
