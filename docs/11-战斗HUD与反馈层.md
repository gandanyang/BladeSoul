# 11 · 战斗 HUD 与反馈层

> 本文档回答一个问题：**玩家怎么知道自己刚才做对了没有。**
> 关联：02 §7 反馈表 / 05 §4.3 色盲要求 / 09 §3 与 10 §1 的颜色纪律。

---

## 0. 为什么现在必须做（一次排期纠错）

三个机制（弹开 / 一闪 / 闪避）已经能跑，有音效、有粒子、有顿帧——
但**玩家读不出来**。实测反馈：

> "弹开、一闪成功没成功没提示；没有伤害数字、交互提示、怪物架势槽；没有人物自己的血槽和其他 UI。"

原计划把 HUD 排在 **M4（垂直切片）**。**这个排法错了。**

> **反馈层不是内容，是核心机制的可读性。**
> M1 唯一的验收标准是"**弹开成功时会想再试一次**"——
> 而这件事**依赖玩家能不能读懂自己刚做了什么**。读不出来，就永远谈不上"想再试一次"。

所以 HUD 提前到 **M1 的一部分**，与弹开同优先级。

---

## 1. 一条原则

> **HUD 的每一个像素都要回答"我现在该做什么"。**

不显示装饰性信息，不做"看起来像游戏"的边框与花纹。
这个界面在暗黑战国的低饱和画面里，越安静越好。

---

## 2. 颜色纪律（延续 09 / 10）

| 元素 | 颜色 | 理由 |
|---|---|---|
| **玩家血条** | 暖白 / 浅琥珀（`#D9C9A8`） | **不用红**——红是敌人与血的专属（10 §1） |
| **玩家体干条** | 浅青灰（`#9FB3B8`），**向上生长** | |
| **敌方血条** | 暗红（`#7A1418`） | |
| **敌方架势槽** | 血红 → 亮红，**左右收缩** | |
| 弹开提示 | 白蓝（`#BFE3FF`） | 与弹开火花同色 |
| 一闪提示 | 高对比黑白 | 与一闪的全屏闪同源 |

> **形状区分优先于颜色区分**（05 §4.3 色盲要求）：
> 玩家条**向上生长**、敌人条**左右收缩**——灰度下也能分清谁是谁。
> 这条不是可选项，是 M6 的可及性验收项，现在就要按它做。

---

## 3. 玩家状态（左下角）

```
  ▮▮▮▮▮▮▮▮▮▮▯▯▯   血
  ▮▮▮▮▮▮▯▯▯▯▯▯▯   体干（向上生长）
  ● ● ● ○ ○        喝血次数
```

| 元素 | 行为 |
|---|---|
| 血条 | 受击时**闪一下白**（不是红——红留给敌人）；扣血部分延迟回落，让玩家看清扣了多少 |
| 体干条 | **向上生长**；停止受击后可见地缓慢回落——让"体干在恢复"这件事本身可读 |
| 喝血次数 | 小瓶/圆点图标，用完变灰 |
| 鬼力槽 | **本卡不做**（M3 一闪家族之后） |

---

## 4. 敌人状态

### 4.1 锁定目标（屏幕上方居中）

名字 ＋ 血条 ＋ **架势槽** ＋ 忍杀标记位

### 4.2 未锁定的敌人（头顶）

一根很细的双色条（血 + 架势）。**只在受伤或靠近时显示**——
否则同屏 8 个敌人会挂满条，画面立刻变成仪表盘。

### 4.3 ★ 架势槽是这套 UI 里最重要的一条

它回答的问题是：**"我还差几下？"**

没有它，弹开就只是"打中了"；有了它，弹开才是"**我在推进**"（01 §1 的北极星：
玩家要能感觉到自己变强了，而不是数字变大了）。

> 规则：**弹开成功时，敌方架势槽必须有一次明显可见的跳动**，
> 而且要能一眼看出"这一下削得比普攻多"（弹开 18 vs 普攻 8）。

---

## 5. 战斗反馈

### 5.1 弹开 / 一闪的成功提示

分三层，从弱到强：

| 层 | 内容 | 现状 |
|---|---|---|
| 1 | 音效 + 火花 + 顿帧 | ✅ 已实现 |
| 2 | **屏幕边缘的颜色脉冲**（弹开=白蓝 / 一闪=黑白）＋ 准心变化 | 本卡新增 |
| 3 | **文字提示**：「弹开」「一闪」短暂出现 | 本卡新增，**默认开启、可在设置里关** |

> **为什么给文字**：M1 阶段玩家必须能**确定**自己刚才是成还是没成。
> 等手感验证通过（"会想再试一次"成立）之后，这个开关应当默认关掉——
> **它是脚手架，不是永久 UI。**
>
> 这也符合 05 §6：不写任何暗示玩家技术差的文案。"弹开"是事实陈述，不是评价。

### 5.2 伤害数字

- 从**命中点**飘出，0.6 秒淡出，小字号，不遮挡画面中心
- **只显示玩家造成的伤害**；玩家自己挨打用"血条闪白 + 屏幕边缘暗红"表达
  （自己身上飘红字会让画面变脏，而且是负反馈，我们不需要强化它）
- **一闪的伤害用更大的字号与不同颜色**——那是"大数字"的时刻
- 可在设置里关闭

### 5.3 交互与处决提示

- 靠近可交互物 / 出现忍杀时机 → 屏幕中下方一组提示（按键 + 动作名）
- **危攻击不在 HUD 重复提示**：敌人身上已经有 `PerilousCue` 的红闪（10 §4）

## 6. 数据来源（不许新造通道）

| 需要什么 | 从哪来 |
|---|---|
| 玩家 / 敌人的血与体干 | `ICombatActorDebug` ＋ Godot 组 `player` / `combat_actor` |
| 结算（弹开 / 一闪 / 伤害） | `EventBus.HitResolved`（已带 `Verdict` / `Damage` / `PostureDamage`） |
| 血 / 体干变化 | `EventBus.HealthChanged` / `PostureChanged` |

**已有接口基本够用。** 唯一缺的是"**喝血剩余次数**"——
需要给 `ICombatActorDebug` **追加**一个只读成员（**只加不改**，改完在报告里登记）。

---

## 7. 硬约束

1. **HUD 只读**，绝不反向影响战斗逻辑（04 §4 的订阅纪律）。
   验收方式和 T28 一样：**灌一个超额事件进去，战斗数值一个都不许变**。
2. `_Process` / `_PhysicsProcess` 里**禁止 `new`**；每帧拼字符串要复用缓冲。
3. 订阅者必须在 `_ExitTree` 里退订（AGENTS.md 铁律）。
4. **60fps 优先**：HUD 不许拖累帧率（07 §7 的降级顺序里，UI 排在最后砍）。
5. 数值（条的颜色、字号、淡出时长）进 `.tres` 或 `[Export]`，**不许写死**。
