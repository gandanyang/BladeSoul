# 10 · 敌人 / 场景 / 特效 美术设定

> 主角见 [09-主角外观设定](09-主角外观设定.md)。资产需求清单见 [07-资产清单与工具链](07-资产清单与工具链.md)。
> 本文只回答"**长什么样**"，给建模 / 特效 / 关卡美术用。

## 0. 一条压倒一切的约束

> **敌人必须让玩家看得出"它曾经是个人"。**

这不是美术口味，是**叙事要求**（03 §2.5 / §4.0）：

- 序章第三幕，魔骸首领会说一句人话——**"疼……"**
- 进入「共鸣」后，主角开始听见杂兵的片段——**"……别抢……这是给孩子的……"**

如果敌人做成一坨抽象的怪物，**这两处会完全失效**。
所以每一类魔骸都要保留**它生前身份的可读残迹**：足轻的阵笠、枪兵的长枪、武士的胴。

---

## 1. 魔骸通用设计语言

| 项 | 设定 |
|---|---|
| 主色 | **黑 + 血红**（`#141014` / `#7A1418`） |
| 发光 | 伤口与眼窝内**透出红光**（`#C8323A`）。**越强的敌人越亮** |
| 皮肤 | 灰黑、湿、无光泽；关节处**不自然地细长**（像被拉长过） |
| 轮廓 | **佝偻、不对称**；一侧手臂常比另一侧粗 |
| 动态 | **抽搐、卡顿**——动作本身是对的（还会用刀），但节奏是坏的 |
| 装备 | **残破但仍在用**：甲片掉了、绑绳断了，可它还在用那个姿势站着 |

**与主角的对比**（07 §3.1 要求"一眼能区分"）：

| | 主角（09） | 魔骸 |
|---|---|---|
| 主色 | 褪色蓝灰 + 土褐 | 黑 + 血红 |
| 饱和度 | **低** | 高 |
| 轮廓 | 干净、瘦、直立、对称 | 佝偻、不对称 |
| 发光 | **只有笼手**，且弱 | 伤口/眼窝，强 |
| 动态 | 有节奏 | 抽搐 |

> ⚠️ **这就是"主角身上不许出现红色"的原因**（09 §3）：玩家必须能在一瞬间靠颜色分辨"谁是人"。

## 2. 敌人类型

### 2.1 魔骸足兵（基础杂兵，最先做）

| 项 | 设定 |
|---|---|
| 生前 | 足轻 |
| 可读残迹 | **阵笠**（歪的、破的，但还戴着）+ 残破胴 + 一支断枪或打刀 |
| 体型 | 比主角略矮、略宽（他生前是个农夫兵） |
| 危险信号 | **唯一没有发光的地方是脸**——红光从阵笠的阴影里透出来 |
| 三角面 | MVP ≤ 12k，最终 ≤ 20k |

> **设计意图**：阵笠是它唯一还"整齐"的东西。玩家看久了会意识到——
> **它死前把笠戴正过。**

### 2.2 魔骸枪兵（危·突刺的载体）

| 项 | 设定 |
|---|---|
| 可读残迹 | 完整的长枪（**枪身完好**，因为枪不是它身体的一部分）+ 破损的具足 |
| 体型 | **瘦长、站得比别的魔骸直**——它还记得枪兵的姿势 |
| 危险信号 | 长枪尖端有**微弱的红光拖尾**（对应 02 §3 的「危」高音预警） |
| 三角面 | ≤ 12k / 20k |

> **设计意图**：它是所有魔骸里**姿势最"人"的一个**——因为它练枪练了一辈子。

### 2.3 精英 · 魔骸武士（第一章队长）

| 项 | 设定 |
|---|---|
| 可读残迹 | **一整套完整的旧武士盔甲**（不是残破的——它是精英，装备好） |
| 恐怖点 | **盔甲是好的，人已经不对了**。面颊（面具）下透出的红光、甲片缝隙里渗出的紫色 |
| 体型 | 比足兵高一个头；肩甲夸张但不对称 |
| 危险信号 | 全身紫黑 + 强发光（与主角的弱紫形成对比：**它已经走到头了**） |
| 三角面 | ≤ 20k / 35k |

> **设计意图**：它就是主角的**可见未来**（03 §2.5"每一个人都是主角可能成为的样子"）。
> 所以它的紫，和主角笼手的紫**必须是同一套颜色**——只是浓得多。

### 2.4 魔骸首领（序章，1.0 之后可复用为小 BOSS）

见 03 §4.0 第三幕。要点：

- **第一阶段"真的会正常打"** → 造型上必须**还像个人**（有完整甲胄、有姿态）
- **第二阶段吞噬尸体后** → 造型**实时变**：体型膨胀、甲片崩开、发光变强
- 说"疼……"的那一瞬间，**它的脸必须是可读的**——这是全序章最重要的一次特写

## 3. 场景

### 3.1 全局（07 §7 已定，这里只落成做法）

| 项 | 做法 |
|---|---|
| 时间 | **多为黄昏 / 雨夜**——统一色调，同时降低贴图精度要求 |
| 雾 | **体积雾**。它同时是氛围和"遮住远景低模"的省钱手段 |
| 光源 | **灯笼是唯一的暖色点**。数量要控制（暖色=注意力，多了会抢读招） |
| 材质 | 湿（石板、木）→ 高光反射，减少细节贴图需求 |

### 3.2 战斗区域的硬要求（03 §7，不可违反）

1. **背景必须低饱和、低对比**——敌人的黑红和主角的灰蓝要能跳出来
2. **不能贴墙打**：战斗区域要留出至少 8m×8m 的空地
3. **地面不能有高频图案**（碎石子、草叶）——会干扰判定距离的判断
4. **垂直元素要少**：柱子、栏杆会挡住读招

### 3.3 第一关：岐阜城下（M4）

| 区域 | 视觉要点 |
|---|---|
| 城下町 | 湿石板路 + 木质町屋；**门窗大多破着，但有几户还亮着灯**（幸存者） |
| 废弃神社 | 鸟居、石阶、积雪/落叶；**一个还没熄灭的香炉** |
| 地下水道 | 全暗，只有主角笼手与敌人伤口的光——**这里是最好的"笼手就是光源"的展示** |

### 3.4 ★ 模块网格与净空规格（**做资产之前必须先定死**）

模块化套件只有在**尺寸对齐**时才是积木；尺寸不对，每一块都得单独修。
所以这几个数字**先冻结**，白盒和资产都按它走。

| 项 | 规格 | 理由 |
|---|---|---|
| **主格距** | **4m**（子格 1m） | 走路 4.2m/s ≈ 一格一秒；够大、省件数 |
| **一层净高** | **3.2m**（含梁 3.6m） | 战国町屋的真实尺度 |
| **门洞** | **1.2m**（单人）／ **2.4m**（通路） | 通路要能让战斗通行 |
| **★★ 可走落差** | **≤ 0.2m**（或改成坡道） | **`CharacterBody3D` 没有自动步高**——超了就卡住。战斗区内的台阶必须是坡道或 2~3 级小台阶 |
| **战斗区净空** | **≥ 8m × 8m**，垂直 ≥ 4.5m | 见下 |

#### ★ 一个从摄像机倒推出来的硬约束（容易漏）

玩家相机的 `SpringArm3D` 长度是 **4.2m**，碰撞层是 World。

> **所以：室内战斗区域的天花板低于 ~4.5m 时，镜头会被顶到贴脸。**

结论（二选一，不许含糊）：
- **要么**室内战斗区净高做到 **≥5m**（寺院正殿、天守大厅这种本来就有高天花板的场景，天然合适）
- **要么**该区域做**露天或半露天**（破顶、廊下、庭院）——这也正好符合 07 §7"多为黄昏/雨夜"的省钱选择

**町屋那种 3.2m 层高的室内，只适合"通过"和"剧情"，不适合打架。** 这条要在白盒阶段就摆对。

### 3.5 模块清单（按优先级）

| 优先级 | 模块 | 用途 |
|---|---|---|
| **P0** | 地面（土／湿石板／木地板）、墙（土壁／板壁／石垣）、门洞 | 任何场景都要 |
| **P0** | 灯笼（挂式／立式） | **它是画面里唯一的暖色**（07 §7），也承担引导视线 |
| **P1** | 町屋：屋顶（茅／瓦）、格子窗、门帘 | 城下町 |
| **P1** | 神社：鸟居、石阶、香炉、赛钱箱 | 废弃神社 |
| **P1** | 自然：竹、松、草、石 | 填充与遮挡 |
| **P2** | 城郭：石垣、天守部件、橹 | 序章／终章 |
| **P2** | 水道：拱形石壁、水面、暗渠 | 地下水道 |

### 3.6 性能与 LOD 纪律

| 项 | 要求 |
|---|---|
| 材质 | **共享材质**：地面/墙面各一套为主，靠 UV 与顶点色变化，**不要每块一个材质** |
| 单件三角面 | 墙面/地面模块 ≤ 300；装饰件 ≤ 1.5k；大结构（鸟居/天守件）≤ 8k |
| Draw Call | ≤ 800（07 §7）→ **能用一件做完的别拆成三件** |
| LOD | 大结构（天守、鸟居）做 2 级 LOD；小件不做 |
| 遮挡 | **雾是主要的遮挡手段**（07 §7），不要靠堆细节去挡远景 |

### 3.7 铺装落地（T33，2026-09-14）——做法与两个必踩的坑

P0 的 11 个模块已生成并铺进 `Dojo` / `L01_Gifu`。
生成器 `tools/gen_kit.py`，铺装器 `tools/gen_level_kit.py`（**只做加法**：读现有 `.tscn`、
把模块作为新节点追加，原有行一行不动；因此布局不可能被改，且可重入、可回退）。
完整交接见 `T33-HANDOFF.md`。

**为什么模块必须"包络"套在白盒外面**：`CSGBox3D` 同时是**碰撞体**与**布局**。
模块只做外观、一个字节不碰碰撞 → `LevelWhiteboxTest` 的可走性/净空自检继续有效，
它顺便就成了"这次铺装有没有动到布局"的判据。

#### 坑 1 · `.glb` 在 Godot 里是 **PackedScene**，不是 Mesh

```tscn
; ✗ 类型不符 → 网格压根不出来（实测对比图只有 0.69% 差异，几何根本没渲染）
[node name="Kit_X" type="MeshInstance3D" parent="Dressing"]
mesh = ExtResource("kit_1")

; ✓ 实例化 PackedScene，再把材质覆盖写进实例内部（照抄 gen_level_whitebox._showcase）
[node name="Kit_X" parent="Dressing" instance=ExtResource("kit_1")]
position = Vector3(...)
scale = Vector3(...)          ; ⚠️ 必须在 rotation 之后：set_rotation 是整个替换 basis

[node name="world" index="0" parent="Dressing/Kit_X"]

[node name="kit_floor_wood" index="0" parent="Dressing/Kit_X/world"]
material_override = ExtResource("kit_7")
```

内层路径不是猜的：trimesh 导出的 glb 结构恒为 `world`(容器) → `kit_<模块名>`(网格)，
Godot 再在外面包一层同名根节点（对照魔骸是 `world/geometry_0`）。

#### 坑 2 · glTF 导入**不会**打开 `vertex_color_use_as_albedo`

本地生成的模块**没有 UV/贴图、全靠顶点色**，而且 trimesh 导出的 glb 里**根本没有材质**
（`materials: null`）。不套材质 = 一片默认灰。所以上面那个 `material_override` 覆盖块
**不是可选项**——魔骸当初也是因为这条才需要 `_showcase`。

**验收判据不要只看"变了多少"**：灰也是"变了"。要看变化区的**平均饱和度**
（灰≈0，我们的模块 >0.20）与**色相桶数**（>1 说明多种顶点色都上了）。
脚本：`.workbuddy/tmp/shot_diff.py`。

## 6. 场景参考与 IP 禁区

**可以查真实原型**（03 §3：历史地名属于公有领域）：
岐阜城、安土城、比叡山延历寺、战国城下町、町屋、鸟居。**真实历史和建筑学是安全且免费的参考。**

**不要**参考/接近：
- 《只狼》的苇名城及其屋顶、天守的具体造型
- 《鬼武者》系列的既有场景与美术风格
- 任何近期 3A 和风游戏里可辨识的场景构图

> 差异化要点（与 10 §1 的角色纪律同源）：
> **我们不需要一个"好认的日本城堡"，我们需要一个"低饱和、被雨和雾吃掉一半、只有灯笼是暖色"的空间。**
> 省美术，而且和魔骸的黑红天然形成对比。

## 4. 特效（07 §3.3 的落地）

**所有战斗特效都由 `EventBus.HitResolved` 驱动**——它已经带着 `Verdict` / `Damage` / `HitStopFrames`。
特效层只订阅事件，**不许反过来影响战斗逻辑**（04 §4 的订阅纪律）。

| 特效 | 触发 | 视觉 | 优先级 |
|---|---|---|---|
| **弹开火花** | `Verdict.Deflect` | 白蓝火花，从武器接触点向外**短促**喷射（8 帧内结束） | **P0** |
| **拼刀大颗粒火花** | `Verdict.Clash` | 更大、更慢、带拖尾的橙白火星 | **P0** |
| **命中血雾** | `Verdict.Hit` | 深红雾状，**方向与刀路一致**（不是爆开） | **P0** |
| **一闪黑白闪** | `Verdict.Issen` | 全屏 0.1s 高对比 + 血雾 + 拖尾 | **P0** |
| 体干破裂碎片 | `Verdict.GuardBreak` | 甲片/骨片飞散 | P1 |
| 魂火 | 击杀（已实现） | 黑紫自发光球（**已经做了**，M7 再美化） | ✅ 已有 |
| 危预警标记 | 敌人发动危招式（已实现） | 红闪（**已经做了**） | ✅ 已有 |
| 刀光轨迹 | 所有攻击 | `RibbonTrailMesh` 或自制，**只在大招上用** | P1 |

> ⚠️ **特效的第一原则是"不能盖住判定"**：
> 弹开与拼刀的火花必须**短**（≤8 帧），否则玩家看不清下一刀什么时候来。
> 华丽是二闪/忍杀的事，不是防御反馈的事。

## 5. 贴图与性能预算

| 项 | 预算 |
|---|---|
| 角色贴图 | 2K（主角）/ 1K（杂兵，可复用） |
| 场景材质 | 尽量**纯色 + 粗糙度变化**，少用大图 |
| 同屏三角面 | ≤ 150 万（07 §7） |
| 同屏敌人 | ≤ 8 |
| 掉帧降级顺序 | **① 体积雾 → ② 粒子数量 → ③ 同屏敌人数**（07 §7 已裁定） |

> 降级顺序里**没有"降分辨率"和"降帧率"**——60fps 优先于画面（01 §0 的精神）。
