### 铁律

> **`scenes/` 放结构，`data/` 放数值，`src/` 放逻辑。三者不许交叉。**

这条规矩是为了对抗 C# 最大的痛点：**改代码要重新编译**。
把数值全放到 `data/*.tres`，90% 的平衡调整就变成了在编辑器里拖滑条，**零编译零重启**。

## 4. AutoLoad 与事件总线

```csharp
// src/Core/EventBus.cs
using System;
using Godot;
using Oniblade.Combat.Data;

namespace Oniblade.Core;

public partial class EventBus : Node
{
    public static EventBus Instance { get; private set; }

    // 内部通信用纯 C# event（比 Godot signal 快，且强类型）
    public event Action<int, int> HealthChanged;      // actorId, value
    public event Action<int, int> PostureChanged;     // actorId, value
    public event Action<int>       PostureBroken;     // actorId
    public event Action<HitEvent>  HitResolved;       // 裁决结果广播
    public event Action<int>       ActorDied;
    public event Action<SoulType, int> SoulGained;

    public override void _EnterTree() => Instance = this;
    public override void _ExitTree()  => Instance = null;

    public void RaiseHealthChanged(int id, int v) => HealthChanged?.Invoke(id, v);
    public void RaiseHitResolved(in HitEvent e)   => HitResolved?.Invoke(e);
    // ...
}
```


### C# event 内存泄漏警告

`static` / 单例上的 C# event 会**强引用**订阅者。节点被 `QueueFree()` 后，
如果没退订，这个事件会一直持有已释放对象的引用（在 C# 侧还活着 → 报
`ObjectDisposedException` 或静默泄漏）。

**规矩**：每个订阅者必须在 `_ExitTree()` 里退订。

```csharp
public override void _ExitTree()
{
    if (EventBus.Instance is { } bus)
    {
        bus.HitResolved -= OnHitResolved;
        bus.ActorDied   -= OnActorDied;
    }
}
```

需要编辑器里连线的地方（UI 按钮等）才用 Godot `[Signal]`，游戏内部一律用 C# event。

## 5. 数据层：Resource + `[GlobalClass]`

`[GlobalClass]` 让 C# 类出现在 Godot 的「新建资源」菜单里，可以直接在编辑器创建 `.tres`。

```csharp
// src/Combat/Data/AttackData.cs
using Godot;

namespace Oniblade.Combat.Data;

public enum DamageType { Slash, Thrust, Blunt, Dark }
public enum IssenKind  { None, Shin, Deflect, Dodge, Clash, Chain }

[GlobalClass]
public partial class AttackData : Resource
{
    [Export] public string    Id   { get; set; } = "";
    [Export] public DamageType Type { get; set; } = DamageType.Slash;

    [ExportGroup("帧数据 (60fps)")]
    [Export] public int StartupFrames   { get; set; } = 8;
    [Export] public int ActiveFrames    { get; set; } = 4;
    [Export] public int RecoveryFrames  { get; set; } = 14;
    [Export] public int CancelFromFrame { get; set; } = 6;

    [ExportGroup("数值")]
    [Export] public int   Damage        { get; set; } = 10;
    [Export] public int   PostureDamage { get; set; } = 8;
    [Export] public float Knockback     { get; set; } = 0.4f;

    [ExportGroup("属性开关")]
    [Export] public bool Unblockable      { get; set; }          // 危：不可格挡
    [Export] public bool Parryable        { get; set; } = true;  // 可弹开
    [Export] public bool IssenVulnerable  { get; set; } = true;  // 可被一闪
    [Export] public bool Thrust           { get; set; }          // 可被看破
    [Export] public bool Perilous         { get; set; }          // 显示「危」

    [ExportGroup("资源")]
    [Export] public Shape3D HitShape { get; set; }
    [Export] public string  AnimName { get; set; } = "";
    [Export] public PackedScene HitFx { get; set; }

    // 派生属性：逻辑帧计算的唯一入口
    public int  TotalFrames          => StartupFrames + ActiveFrames + RecoveryFrames;
    public int  ActiveStart          => StartupFrames;
    public int  ActiveEnd            => StartupFrames + ActiveFrames;
    public int  RecoveryStart        => ActiveEnd;
    public bool IsActiveAt(int f)    => f >= ActiveStart && f < ActiveEnd;
    public bool IsInRecoveryAt(int f)=> f >= RecoveryStart && f < TotalFrames;
    public bool CanCancelAt(int f)   => f >= CancelFromFrame;
}
```

## 6. 判定快照与裁决器（★ 全项目最核心）

### 6.1 快照 struct

```csharp
// src/Combat/Snapshots.cs
using Oniblade.Combat.Data;

namespace Oniblade.Combat;

public readonly struct AttackerSnapshot
{
    public int        ActorId         { get; init; }
    public AttackData Data            { get; init; }
    public bool       IsActive        { get; init; }  // 攻方本帧在判定帧
    public bool       IsAttackAction  { get; init; }  // 攻方本帧在出招（含前摇后摇）
    public bool       IssenVulnerable { get; init; }  // 攻方在"可被一闪"窗口
}

public readonly struct DefenderSnapshot
{
    public int        ActorId         { get; init; }
    public bool       IsInvulnerable  { get; init; }  // 闪避无敌帧
    public bool       InDeflectWindow { get; init; }
    public bool       IsGuarding      { get; init; }
    public int        GuardAngleDeg   { get; init; }  // 攻方相对防御方正面的夹角
    public int        CurrentPosture  { get; init; }
    public int        MaxPosture      { get; init; }
    public IssenKind  IssenKind       { get; init; }  // None = 无 buff

    /// <summary>防御方本帧「也在判定帧」——拼刀判定需要它（不是"在出招"）。</summary>
    public bool       IsActive        { get; init; }
}

public readonly struct ResolveResult
{
    public Verdict Verdict       { get; init; }
    public int     Damage        { get; init; }
    public int     PostureDamage { get; init; }
    public int     HitStopFrames { get; init; }
    public int     SlowMoMs      { get; init; }
    public IssenKind GrantIssen  { get; init; }   // 结算后授予的一闪 buff
    public int     GrantIssenFrames { get; init; }
}
```

### 6.2 裁决器（纯函数，无 Godot 节点依赖）

```csharp
// src/Combat/CombatResolver.cs
using System;
using Oniblade.Combat.Data;

namespace Oniblade.Combat;

public enum Verdict { Miss, Hit, Block, GuardBreak, Deflect, Clash, Issen, Deathblow }

/// ★ 整个游戏的心脏。
/// 纯逻辑，不引用任何 Godot 节点 / 场景树 / 物理服务器，
/// 因此可以在 xUnit 里直接单测（Godot.Vector3 是纯托管结构体，可脱离引擎使用）。
public static class CombatResolver
{
    public const int GuardHalfAngleDeg = 70;

    /// 六条规则，顺序即优先级，命中即返回。
    public static ResolveResult Resolve(in AttackerSnapshot atk, in DefenderSnapshot def)
    {
        // 1. 闪避无敌 → 完全无效
        if (def.IsInvulnerable)
            return new ResolveResult { Verdict = Verdict.Miss };

        // 2. 一闪（防御方持有 buff + 攻方可被一闪）
        if (def.IssenKind != IssenKind.None && atk.IssenVulnerable)
            return IssenTable(def.IssenKind);

        // 3. 拼刀：**双方都在判定帧**（刀对刀真的撞上了）
        //    注意：要求防御方 IsActive，而不是"在出招(IsAttackAction)"——
        //    否则砍一个正在挥空后摇的敌人也会变成拼刀，玩家会觉得莫名其妙。
        if (atk.IsActive && def.IsActive)
            return new ResolveResult
            {
                Verdict        = Verdict.Clash,
                HitStopFrames  = 10,
                GrantIssen     = IssenKind.None,   // 拼刀胜利后才给 buff
            };

        // 4. 弹开
        if (def.InDeflectWindow)
            return new ResolveResult
            {
                Verdict         = Verdict.Deflect,
                PostureDamage   = 18,
                HitStopFrames   = 8,
                GrantIssen      = IssenKind.Deflect,
                GrantIssenFrames = 10,
            };

        // 5. 格挡（角度判定；体干已满则破防）
        //    注意：Unblockable（危）在这里被拦下，直接落到规则 6
        if (def.IsGuarding
            && !atk.Data.Unblockable
            && Math.Abs(def.GuardAngleDeg) <= GuardHalfAngleDeg)
        {
            if (def.CurrentPosture >= def.MaxPosture)
                return new ResolveResult { Verdict = Verdict.GuardBreak, HitStopFrames = 10 };

            return new ResolveResult
            {
                Verdict       = Verdict.Block,
                PostureDamage = atk.Data.PostureDamage,
                HitStopFrames = 6,
            };
        }

        // 6. 命中
        return new ResolveResult
        {
            Verdict       = Verdict.Hit,
            Damage        = atk.Data.Damage,
            PostureDamage = atk.Data.PostureDamage,

            HitStopFrames = 4,
        };
    }

    private static ResolveResult IssenTable(IssenKind kind) => kind switch
    {
        IssenKind.Shin    => new ResolveResult { Verdict = Verdict.Issen, PostureDamage = -1, HitStopFrames = 14, SlowMoMs = 300 },
        IssenKind.Deflect => new ResolveResult { Verdict = Verdict.Issen, PostureDamage = -1, HitStopFrames = 14, SlowMoMs = 300, GrantIssen = IssenKind.Chain, GrantIssenFrames = 12 },
        IssenKind.Dodge   => new ResolveResult { Verdict = Verdict.Issen, PostureDamage = -1, HitStopFrames = 14, SlowMoMs = 300, GrantIssen = IssenKind.Chain, GrantIssenFrames = 12 },
        IssenKind.Clash   => new ResolveResult { Verdict = Verdict.Issen, PostureDamage = -1, HitStopFrames = 14, SlowMoMs = 300, GrantIssen = IssenKind.Chain, GrantIssenFrames = 12 },
        IssenKind.Chain   => new ResolveResult { Verdict = Verdict.Issen, PostureDamage = -1, HitStopFrames = 14, SlowMoMs = 300, GrantIssen = IssenKind.Chain, GrantIssenFrames = 12 },
        _                 => new ResolveResult { Verdict = Verdict.Miss },
    };
}
```

> `PostureDamage = -1` 是"按百分比削体干"的哨兵值，具体百分比在
> `CombatActor.ApplyVerdict()` 里按「杂兵/精英/BOSS」分档处理（见 02 文档 §2.3）。

### 6.3 为什么裁决器要纯函数

1. 可以把 02 文档里的 6 条规则写成 6 个 xUnit 测试，改动优先级时**立刻知道有没有破坏别的规则**
2. 调平衡不需要开游戏
3. 心里踏实 —— 这是全项目最不能出错的地方

### 6.4 ⚠️ 关键细节：不要让裁决器直接吃 `AttackData`

上面 §6.2 的签名写的是 `atk.Data`，但 `AttackData` 是 **Godot `Resource`**——
把它传进"纯函数"会立刻打破"可以在 xUnit 里脱离引擎测试"的前提
（测试进程触碰 Godot 托管类型会抛未初始化异常）。

**正确做法**：加一层不含任何 Godot 类型的 `AttackTraits`，
由 `AttackData.ToTraits()` 转换。裁决器只认 `AttackTraits`。

```csharp
// src/Combat/Snapshots.cs —— 零 Godot 依赖
public readonly struct AttackTraits
{
    public int  Damage        { get; init; }
    public int  PostureDamage { get; init; }
    public bool Unblockable   { get; init; }   // 「危」：格挡与弹开都无效
    public bool Parryable     { get; init; }   // 可弹开

    public static AttackTraits Neutral => new() { Parryable = true };
    public static AttackTraits Perilous => new() { Unblockable = true, Parryable = false };
}
```

对应地，`AttackerSnapshot` 持 `AttackTraits Traits`，不再持 `AttackData Data`；
`AttackData` 侧提供 `ToTraits()`。

这条边界是「裁决器可单测」这个性质的全部成本，非常划算——
一旦有人图省事直接把 `AttackData` 塞进去，整个测试策略就废了。

## 7. 判定框：不用 Area3D 信号，用同步形状查询

### 为什么

`Area3D.AreaEntered` 信号的回调顺序**不确定**，且 `GetOverlappingAreas()`
返回的是**上一个物理帧**的状态，会引入 1 帧延迟。

对帧数据驱动的动作游戏，1 帧延迟是致命的，顺序不确定更是灾难
（同帧双方互击，谁先结算会改变结果）。

### 方案

- **`Hurtbox : Area3D`** —— 只作为"可被查询的标记"，`Monitoring = false`，`Monitorable = true`
- **`Hitbox : Node3D`** —— 不参与物理，只持有一个 `Shape3D`，每帧主动发起查询

```csharp
// src/Combat/Hurtbox.cs
using Godot;

namespace Oniblade.Combat;

public partial class Hurtbox : Area3D
{
    [Export] public CombatActor OwnerActor { get; set; }
```

```csharp
// src/Combat/Hitbox.cs
using Godot;

namespace Oniblade.Combat;

public partial class Hitbox : Node3D
{
    [Export] public Shape3D Shape      { get; set; }
    [Export] public uint    TargetMask { get; set; } = 1;

    public CombatActor OwnerActor { get; private set; }
    public AttackData  Data       { get; private set; }
    public bool        IsActiveThisFrame { get; set; }

    public void Configure(CombatActor owner, AttackData data)
    {
        OwnerActor = owner;
        Data       = data;
        Shape      = data.HitShape;
    }

    /// 同步形状查询。返回写入 buffer 的命中数量。
    /// 用 Span 避免每帧 GC（_PhysicsProcess 里 new List 会持续制造垃圾）。
    public int Query(Span<Hurtbox> buffer)
    {
        if (Shape is null || !IsActiveThisFrame) return 0;

        var space = GetWorld3D().DirectSpaceState;
        var p = new PhysicsShapeQueryParameters3D
        {
            Shape             = Shape,
            Transform         = GlobalTransform,
            CollisionMask     = TargetMask,
            CollideWithAreas  = true,
            CollideWithBodies = false,
        };

        var hits = space.IntersectShape(p, buffer.Length);   // 同步、立即、确定顺序
        int n = 0;
        foreach (var h in hits)
        {
            if (h["collider"].As<Hurtbox>() is not { } hurt) continue;
            if (hurt.OwnerActor == OwnerActor) continue;      // 不打自己
            if (n >= buffer.Length) break;
            buffer[n++] = hurt;
        }
        return n;
    }
}
```

> 如果性能允许，也可以继续用 `GetOverlappingAreas()`；但**顺序问题必须解决**：
> 在 `CombatArbiter` 里按 `ActorId` 排序后再结算，保证同帧结果可复现。

## 8. 战斗仲裁器

每帧只做一件事：**收集所有重叠 → 排序 → 逐个交给裁决器**。

```csharp
// src/Core/CombatArbiter.cs
using System;
using System.Collections.Generic;
using Godot;
using Oniblade.Combat;

namespace Oniblade.Core;

public partial class CombatArbiter : Node
{
    private readonly List<Hitbox>  _hitboxes = new(64);
    private readonly List<Hurtbox> _scratch  = new(16);
    private readonly List<Pending> _pending  = new(32);

    private readonly record struct Pending(
        Hitbox Attacker, Hurtbox Defender, int Priority, int AttackerId);

    public void Register(Hitbox hb)   => _hitboxes.Add(hb);
    public void Unregister(Hitbox hb) => _hitboxes.Remove(hb);

    public override void _PhysicsProcess(double delta)
    {
        _pending.Clear();

        // 1) 收集本帧所有重叠
        foreach (var hb in _hitboxes)
        {
            if (!hb.IsActiveThisFrame) continue;
            _scratch.Clear();
            // 用可复用的 List 承载（避免 Span 跨方法作用域的复杂度）
            int n = hb.Query(CollectionsMarshal.AsSpan(_scratch));
            for (int i = 0; i < n; i++)
            {
                var hurt = _scratch[i];
                _pending.Add(new Pending(hb, hurt,
                    PriorityOf(hb.Data),
                    hb.OwnerActor.ActorId));
            }
        }

        // 2) 排序：保证同帧结果可复现（ActorId → 招式优先级）
        _pending.Sort(static (a, b) =>
        {
            int c = a.Priority.CompareTo(b.Priority);
            return c != 0 ? c : a.AttackerId.CompareTo(b.AttackerId);
        });

        // 3) 逐个结算
        foreach (var p in _pending)
            p.Attacker.OwnerActor.ResolveAttack(p.Attacker, p.Defender);
    }

    /// 一闪 > 拼刀 > 弹开 > 普攻
    private static int PriorityOf(AttackData d) => d is null ? 99 : 50;
}
```

> `CollectionsMarshal.AsSpan` 需要 `using System.Runtime.InteropServices;`，
> 或者直接把 `Query` 写成接收 `List<Hurtbox>` 的重载。二选一，别为这个纠结。

## 9. 状态机（状态是 POCO，不是 Node）

**关键决策**：状态类**不继承 Node**。理由：
- 不污染场景树、不在 Inspector 里出现
- 无节点生命周期开销（几百个状态对象也是零成本）
- **可以被单元测试直接实例化**（GDScript 做不到这点）

```csharp
// src/Combat/States/ActorState.cs
namespace Oniblade.Combat.States;

public abstract class ActorState
{
    protected CombatActor  Actor   { get; private set; }
    protected StateMachine Machine { get; private set; }

    /// 已在本状态持续多少帧（用于帧数据判定）
    public int Frame { get; private set; }

    public void Attach(CombatActor actor, StateMachine machine)
    {
        Actor = actor;
        Machine = machine;
    }

    public virtual void Enter() => Frame = 0;
    public virtual void Exit()  { }
    public virtual void Tick()  => Frame++;

    /// 允许哪些状态打断自己（默认全部允许，具体状态覆写）
    public virtual bool CanTransitionTo(ActorState next) => true;
}
```

```csharp
// src/Combat/States/StateMachine.cs
using System;
using System.Collections.Generic;
using Godot;

namespace Oniblade.Combat.States;

public sealed class StateMachine
{
    private readonly Dictionary<Type, ActorState> _states = new();
    private readonly CombatActor _owner;
    private ActorState _pending;

    public ActorState Current { get; private set; }

    public StateMachine(CombatActor owner) => _owner = owner;

    public T Add<T>(T state) where T : ActorState
    {
        state.Attach(_owner, this);
        _states[typeof(T)] = state;
        return state;
    }

    public T Get<T>() where T : ActorState => (T)_states[typeof(T)];

    /// 延迟到本帧 Tick 结束后再切换，避免在 Tick 中途换状态导致 Frame 混乱
    public void Change<T>() where T : ActorState => _pending = _states[typeof(T)];

    public void Tick()
    {
        Current?.Tick();

        if (_pending is not null && _pending != Current)
        {
            if (Current is null || Current.CanTransitionTo(_pending))
            {
                Current?.Exit();
                Current = _pending;
                Current.Enter();
            }
            _pending = null;
        }
    }
}
```

**「延迟切换」这个细节很重要**：如果允许在 `Tick()` 内部直接改 `Current`，
那么当前状态的 `Frame` 会在同一帧被重置，帧数据判定就会出现 1 帧偏移。
所有状态切换请求统一排队到帧末处理。

## 10. 顿帧（逐 actor 冻结）

```csharp
// src/Combat/CombatActor.cs（节选）
using Godot;

namespace Oniblade.Combat;

public abstract partial class CombatActor : CharacterBody3D
{
    public int  ActorId        { get; set; }
    public bool IsAttackAction { get; protected set; }

    private int _hitStopFrames;

    public override void _PhysicsProcess(double delta)
    {
        // 顿帧：只冻结自己，不冻结世界
        if (_hitStopFrames > 0)
        {
            _hitStopFrames--;
            Velocity = Vector3.Zero;
            return;                     // 状态机不 tick，动画不推进
        }

        TickTimers();                   // 体干回复、buff 倒计时等
        Machine.Tick();
        ApplyMovement(delta);
    }

    /// 取最大值而非覆盖：同时命中多个目标时，取最长顿帧
    public void ApplyHitStop(int frames)
    {
        if (frames > _hitStopFrames) _hitStopFrames = frames;
    }
}
```

### 与 `Engine.TimeScale` 的分工

| 用途 | 手段 | 影响范围 |
|---|---|---|
| 命中顿帧（普攻/弹开/拼刀/体干破） | 逐 actor `_hitStopFrames` | 只冻结参战者 |
| 一闪/忍杀慢镜 | `Engine.TimeScale = 0.25` + Tween 恢复 | 全局 |

慢镜必须用 Tween 平滑恢复：

```csharp
private async void PlaySlowMo(float scale, double durationSec)

```

## 11. 输入缓冲

```csharp
// src/Player/PlayerInputBuffer.cs
using System;
using Godot;

namespace Oniblade.Player;

/// 纯逻辑，可单测（注入一个"本帧按下了什么"的委托即可脱离 Input 单例）
public sealed class PlayerInputBuffer
{
    private const int Capacity = 16;

    private readonly (StringName Action, int Frame)[] _ring = new (StringName, int)[Capacity];
    private readonly Func<StringName, bool> _isJustPressed;
    private int _head, _count, _frame;

    public PlayerInputBuffer(Func<StringName, bool> isJustPressed)
        => _isJustPressed = isJustPressed;

    public static readonly StringName[] Watched =
    {
        "attack", "guard", "dodge", "lock_on", "interact", "oni_magic",
    };

    /// 在每个 _PhysicsProcess 的最开头调用
    public void Poll()
    {
        _frame++;
        foreach (var a in Watched)
            if (_isJustPressed(a)) Push(a);
    }

    private void Push(StringName action)
    {
        if (_count < Capacity)
        {
            _ring[(_head + _count) % Capacity] = (action, _frame);
            _count++;
        }
        else
        {
            _ring[_head] = (action, _frame);
            _head = (_head + 1) % Capacity;
        }
    }

    /// 在 windowFrames 帧内是否按过该动作；命中则消费掉，避免被两个状态重复读取
    public bool Consume(StringName action, int windowFrames)
    {
        for (int i = 0; i < _count; i++)
        {
            int idx = (_head + i) % Capacity;
            if (_ring[idx].Action == action && _frame - _ring[idx].Frame <= windowFrames)
            {
                RemoveAt(i);
                return true;
            }
        }
        return false;
    }

    private void RemoveAt(int logicalIndex)
    {
        int idx = (_head + logicalIndex) % Capacity;
        for (int i = logicalIndex; i < _count - 1; i++)
        {
            int a = (_head + i) % Capacity;
            int b = (_head + i + 1) % Capacity;
            _ring[a] = _ring[b];
        }
        _count--;
    }

    public int CurrentFrame => _frame;
}
```

`Consume` 而不是 `Peek`：**一次输入只能被一个状态消费**。
否则「攻击」会被 `AttackState` 和 `GuardState` 同时读到，产生幽灵行为。

### 帧率对齐（必须统一）

- **全项目基准 60fps**。动画资产的导入 FPS 在 `.import` 里设为 `60`
- Mixamo 默认 30fps → 导入时设 `FPS=30` 会与逻辑帧不一致，
  所以**要求所有动作资产按 60fps 导出**，或在导入后重采样
- **验收方法**：调试面板同时显示「动画当前帧」和「逻辑帧」，
  偏差 > 2 帧就在面板上爆红。这是动画与帧数据打架的唯一早期信号

## 16. C# 特有的坑（踩过的都写在这）

| 坑 | 现象 | 对策 |
|---|---|---|
| **无热重载** | 改一行代码必须 Build + 重启游戏 | 数值全部外置 `.tres`（本项目最重要的一条） |
| `partial` 漏写 | 编译期报源生成器错误，提示莫名其妙 | 所有 `Node` / `Resource` 派生类一律 `public partial` |
| `[Export]` 用属性 | C# 里 export 字段无效 | 统一 `[Export] public T X { get; set; }` |
| C# event 泄漏 | 节点释放后仍被单例引用 | 每个订阅者在 `_ExitTree()` 退订 |
| 信号命名约定 | `[Signal] delegate void XxxEventHandler` → `SignalName.Xxx` | 编辑器连线才用 `[Signal]`，内部通信用 C# event |
| 编辑器 Build 与 CLI 不一致 | 两边输出目录不同，出现"改了没生效" | 调参期统一用编辑器 Build 按钮；CI 才用 `dotnet build` |
| Nullable 警告泛滥 | 后期开启会一次性冒出几百个警告 | **一开始就开** `<Nullable>enable</Nullable>` |
| 场景加载 | 直接 `Instantiate()` 拿不到泛型 | `ResourceLoader.Load<PackedScene>(path).Instantiate<T>()` |
| 节点唯一名 | 路径字符串一改就崩 | 用 `%UniqueName` 语法 + `GetNode<T>("%Hud")` |

## 17. 命名与工程约定

- 命名空间 `Oniblade.<Layer>`，**file-scoped namespace**（`namespace X;` 而非大括号）
- 私有字段 `_camelCase`，公开属性 `PascalCase`，常量 `PascalCase`
- 类后缀语义：`XxxState` / `XxxData` / `XxxManager` / `XxxActor` / `XxxProfile`
- 一个文件一个公开类；文件名 = 类名
- 每个 `[Export]` 都用 `[ExportGroup]` 分组，否则 Inspector 会变成一坨
- 帧相关的数字**永远加 `Frames` 后缀**（`StartupFrames` 而非 `Startup`），
  防止有人误当毫秒用
